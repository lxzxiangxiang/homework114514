项目文档：球球大作战风格游戏（C++/Qt Windows 完整版）

1. 项目概述

1.1 项目名称

Agar.io Clone – 球球大作战完整复刻版

1.2 项目目标

基于提供的 Python + Pygame 完整实现，使用 C++17 与 Qt 6 框架在 Windows 平台开发一款单人游戏。玩家球体成长、分裂、吐孢、多种技能与危险物、AI 等级与决策、同体吸引合并、空间网格碰撞优化等。代码结构清晰，性能稳定 60 FPS。

1.3 技术特点

· 语言：C++17
· 图形框架：Qt Widgets + QGraphicsView / QGraphicsScene / QGraphicsItem
· 构建工具：CMake
· 输入：键盘（WASD、空格、E、ESC、M、回车）
· 动画：非必要不添加额外动画，保持与原版一致的瞬态反馈；但可使用 QPropertyAnimation 实现分裂/合并等平滑过渡（可选）

2. 功能需求（完整保留原版特性）

2.1 核心玩法

· 成长：玩家通过吞食豆子、技能球、抛射物以及比自己小的 AI 球体增加质量。质量 = π × 半径²，半径越大移动速度越低（速度 = 基础速度 × sqrt(最小半径 / 当前半径)）。
· 捕食规则：若球体 A 半径 > 球体 B 半径 × 1.1，且 B 无护盾，则 A 可吞食 B。
· 分裂：半径 ≥ 18 时，按空格分裂。新球体半径 = 原半径 / √2，朝移动方向弹出。分裂后同源球体之间会相互吸引并最终合并。
· 吐孢：半径 ≥ 25 时，按 E 键吐出一个孢子（半径 8），自身半径减少 3。孢子可被任何球体吞食。
· 胜利条件：玩家所有球体总半径 ≥ 2000。
· 失败条件：玩家所有球体被吞食。

2.2 实体列表

实体 属性 行为
豆子 (Food) 半径 3~8，随机颜色 静止，被吞食后在地图随机位置重生
技能球 (SkillBall) 半径 12，带脉冲光效 每 5 秒概率生成，最多 8 个；存在 30 秒后消失。触碰后赋予对应技能
危险物 (Hazard) 半径 50，三种类型 每 15 秒概率生成，最多 8 个；存在 45 秒。触碰后施加减益效果
抛射物 (EjectBall) 半径 8，与吐孢者同色 以 8 像素/帧速度飞出，逐渐减速，存在 20 秒
AI 球体 (Ball) 半径 15~60，随机颜色 分 1、2、3 级，自主决策移动、吃豆、躲避、追击、分裂

· 新生成的玩家球体拥有 3 秒无敌时间（闪烁提示）。

2.4 AI 行为系统

等级差异

等级 反应时间 决策间隔 转向速度 分裂倾向
1 0.5 秒 0.4 秒 2.0 rad/s 无
2 0.3 秒 0.2 秒 3.0 rad/s 有（猎食或逃生时）
3 0.15 秒 0.1 秒 5.0 rad/s 有（更激进）

决策流程（每 decision_interval 执行一次）

1. 威胁检测：检测半径大于自己 1.1 倍的球体，按危险程度排序，若威胁距离 < 自身半径×6，则朝反方向逃离。
2. 猎物检测：检测半径小于自己 0.9 倍的球体，按价值（猎物半径/距离）排序，朝最有价值猎物移动。
3. 巡逻：若无威胁与猎物，随机选择地图内巡逻点移动。
4. 分裂决策（等级≥2）：若目标猎物距离 < 自身半径×4 且自身半径大于猎物半径 1.5 倍，则朝猎物方向分裂；若威胁距离 < 自身半径×3，则朝逃离方向分裂。

移动与转向

· 使用 current_direction 和 target_direction，每帧平滑转向（最大转角 = turn_speed * dt）。
· 同 AI 组（相同 ai_id）球体之间有相互吸引力，促使合并。

2.5 同源球体合并机制

· 属于同一玩家或同一 AI 组的多个球体会产生吸引力，随时间增大逐渐靠近。
· 当两个同源球体圆心距离 < 两者半径之和时，会自动合并为一个球体（半径 = sqrt(r1² + r2²)）。
· 吸引力=常数引力+距离引力*距离^2+时间初始引力（随分裂时间衰减）。

2.6 空间网格优化

· 采用 SpatialGrid 类，单元格大小 200×200。
· 每帧更新所有球体到网格，碰撞检测时只检查相邻单元格内的对象，避免 O(N²) 复杂度。

2.7 动态摄像机

· 跟随玩家所有球体的中心点（质量加权平均）。
· 根据玩家平均半径动态缩放：scale = 1.0 / (1 + max(0, (avgRadius - 20) / 80))，范围限制 [0.5, 1.5]。
· 缩放平滑插值（可选，原版使用线性平滑）。

3.3 核心类设计

Entity (QGraphicsEllipseItem)

· 提供位置、半径、颜色、是否存活等基本属性。
· 虚函数 update(qreal dt)、onEaten(Entity* eater)。

Ball : public Entity

· 成员：vx, vy, isPlayer, aiLevel, aiId, splitTimer, mergeTimer, invincibleTimer, skill, skillTimer, debuff, debuffTimer, lastDx, lastDy。
· 方法：move(dx, dy, dt), split(direction), eject(), eat(Entity*), applySkill(), applyDebuff(), isInvincible(), hasShield()。
· 重写 paint() 实现无敌闪烁、技能/负面效果光环。

SpatialGrid

· 使用 QHash<QPair<int,int>, QVector<Entity*>>。
· 提供 clear()，add(Entity*)，getNearby(Entity*)。

AIController

· 静态方法 updateAI(Ball* ai, const QList<Ball*>& allBalls, const QList<Food*>& foods, qreal dt)。
· 内部维护每个 AI 的决策计时器、方向平滑状态（可使用 QHash<Ball*, AIState>）。

GameScene : public QGraphicsScene

· 管理所有实体列表：playerBalls，aiBalls，foods，skillBalls，hazards，ejectBalls。
· 每帧调用 updateGame(qreal dt)：
  1. 处理玩家输入（从 GameView 获取方向）
  2. 更新玩家和 AI 移动（玩家调用 move，AI 通过 AIController 计算方向后调用 move）
  3. 更新抛射物、技能球、危险物的生命周期
  4. 更新所有同源球体吸引力（applyAttraction）
  5. 碰撞检测（使用 SpatialGrid 优化）
  6. 生成新豆子、AI 补充
  7. 检查胜利/失败，更新 HUD
· 提供 spawnFood(int count)，spawnSkillBall()，spawnHazard()，spawnAIBall()。

GameView : public QGraphicsView

· 持有 GameScene 指针。
· 重写 keyPressEvent，mouseMoveEvent（鼠标控制移动方向）。
· 提供 updateCamera() 方法，根据玩家中心点更新变换。
· 管理游戏状态机（State { Menu, Playing, Paused, GameOver, Victory }）。
· 控制 QTimer 驱动场景更新。

UIManager

· 管理 HUD 文本项（QGraphicsTextItem）。
· 提供 showMenu()，showGameOver(int score, float time)，showVictory(int score, float time)，hideUI()。
· 使用独立 QWidget 或场景内绘制矩形+文本（为简单，建议全部在场景内完成）。

3.5 碰撞检测与响应流程（伪代码）

```cpp
void GameScene::checkCollisions() {
    // 1. 更新空间网格
    spatialGrid.clear();
    for (ball : allBalls) spatialGrid.add(ball);
    
    // 2. 球-食物碰撞
    for (ball : allBalls) {
        for (food : foods) {
            if (collide(ball, food)) {
                ball.eat(food); food.alive = false;
                if (ball.isPlayer) score++;
            }
        }
    }
    
    // 3. 球-技能/危险物/抛射物碰撞（类似）
    
    // 4. 球-球碰撞（使用网格减少检查）
    for (ball1 : allBalls) {
        for (ball2 : spatialGrid.getNearby(ball1)) {
            if (ball1 == ball2) continue;
            // 同源合并
            if (sameOwner(ball1, ball2) && canMerge) {
                merge(ball1, ball2);
            } 
            // 吞食
            else if (ball1.radius > ball2.radius * EAT_RATIO && !ball2.hasShield()) {
                ball1.eat(ball2); ball2.alive = false;
            }
            // 反向吞食类似
        }
    }
    
    // 5. 移除死亡实体，补充新实体
}
```

6. 风险与应对

风险 概率 应对
Qt collidingItems() 在实体>300 时性能下降 中 坚持使用空间网格，限制 AI ≤ 30，豆子 ≤ 200，技能+危险物 ≤ 16。
同源吸引力合并导致异常抖动 中 使用平滑吸引力公式（原 Python 代码已验证），合并时半径计算正确。
AI 分裂决策过于复杂导致 bug 高 先实现等级 1 AI，等级 2/3 逐步添加；分裂决策加入计时器避免每帧分裂。
内存泄漏（图元未正确删除） 低 使用 QGraphicsScene 自动管理，调用 deleteLater()。
缩放摄像机时文本 HUD 也缩放 低 HUD 不要添加到 QGraphicsScene，而是直接绘制在 QGraphicsView 的覆盖层（drawForeground）或使用独立 QWidget 悬浮。
